# 商城取消审批配套

商城与后台的 `order_cancel_policy.py` 共用同一业务规则和数据表。

- 本人待付款、部分配货订单可直接取消；已配货及后续状态须申请审批。
- `POST /api/store/orders/{id}/cancellation-requests` 提交必填原因；本人按申请版本调用 `POST /api/store/orders/cancellation-requests/{id}/withdraw` 撤回。
- 提交和撤回不改变订单状态或库存。查询订单返回最新申请进度、本人撤回能力以及驳回意见。
- UI 保持英文。后台身份信息、内部取消备注及后台发起的申请原因不返回商城。
- 新增申请表迁移及受限数据库授权由后台配套发布实施；商城运行时不能审批，不能写内部审计或管理后台账号。

本次只完成本地实现和自动化验收，未部署。后续需与后台成套发布，避免旧版直接取消接口与新版审批规则并存。

本地浏览器自动化脚本 `scripts/verify-order-cancellation-browser.js` 仅允许专用 5397 端口的 `*_test` 夹具。手动开发页面仍按项目约定连接本机 55439 的线上同步镜像库，自动化脚本不写入镜像库或远程生产库。
